## 1. 系统是什么

vnERPNext 是一套**印刷生产经营管理系统（Print MIS）**，覆盖「接单 → 打样 → 排产 → 领料 → 印制 → 质检 → 出入库 → 发货 → 收款」的完整闭环。按业务链条分成六个使用域：

| 分册 | 使用角色 | 主责模块 |
|------|----------|----------|
| 销售 | 业务员 / 跟单 | 销售订单、打样订单、发货、退货、客户跟进 |
| 生产 | 计划员 / 车间 | 工单、工艺/标准卡、印前（制版、打样）、委外、领退料 |
| 仓储 | 仓管 / 物料员 | 入库、出库、调拨、盘点、库存查询、二维码 |
| 采购 | 采购员 | 采购申请、采购订单、供应商、来料跟催 |
| 财务 | 财务 | 应收应付、收付款、成本核算、月度账 |
| 质量 | 质检 / QA | 来料检验、过程/最终检验、不合格品、供应商审核、实验室测试 |

## 2. 登录与访问

| 项 | 说明 |
|----|------|
| 访问地址 | 开发/演示 `http://localhost:5000`；生产地址以运维下发为准（详见《04-运维指南/生产部署.md》） |
| 登录页 | `/login` |
| 账号 | 由系统管理员在「系统管理 > 用户管理」分配，初始账号为工号/邮箱 |
| 首次登录 | 系统标记 `firstLogin=1`，此时除白名单接口外**其他操作会返回 403**，必须**先改密码**再正常作业 |
| 密码规则 | 建议 8 位以上、字母+数字组合；修改密码在「个人中心 / 修改密码」 |
| 语言 | 右上角切换，支持 **简体中文 / 繁體中文 / English / Tiếng Việt** 四语，切换即时生效 |
| 退出 | 右上角「退出登录」，退出后浏览器不再保留会话 Cookie |

**权限提示**：看不到某个菜单，通常是账号没有被授予该菜单权限（页面顶部会提示「当前账号缺少访问该页面所需的权限…请联系管理员分配权限」），找系统管理员加权限即可，不需要重启服务。

## 3. 界面通用约定

### 3.1 左侧菜单
菜单是**数据库驱动**的（`sys_menu` 表），由系统管理员在「系统管理 > 菜单管理」配置。功能改动（新增页面/调整顺序）由管理员维护，业务用户不需要本地配置。

### 3.2 列表页（所有单据列表都一样）
1. **查询区**：关键字搜索 + 下拉筛选（日期区间、状态、客户/供应商等），点「查询」执行，点「重置」清空。
2. **工具栏**：
   -「新增」打开单据表单；
   - 勾选行首复选框可**批量删除**（表头复选框为全选）；
   -「导出」「打印」「扫描」按各模块提供，见对应分册。
3. **列表区**：支持排序、点击行查看详情/编辑；分页在下方，默认每页 10/20 条（各模块可能不同）。
4. **删除是软删除**：记录会置 `deleted=1`，列表默认不显示，但**物理数据仍在库里**。因此删除不等于作废——需要留痕的场景请走「反审核/取消」而非删除。

### 3.3 表单
- 必填字段红色星号，未填保存时前端拦截并提示；
- 「保存」成功会有 toast 提示，列表自动刷新；
- **单据号由系统自动生成**，不允许手改（规则见 §4）；
- 校验失败时后端返回 `AE00xx` 系列错误码，前端直接展示对应中文/越南语/英文文案。

### 3.4 仪表盘
`/dashboard` 首页分板块：总览、CEO 经营看板、销售、生产、仓储、质量、财务看板，另有「数据流向」页可查看跨表链路。看板支持全屏查看。

## 4. 单据编号规则

新增单据时系统按 `前缀 + 日期 + 流水号` 自动编号（例如 `SO202609260004`、`WO20260926000003`、`SP202609260010`）。

| 单据 | 编号字段（库表.列） | 现网样本 |
|------|--------------------|----------|
| 销售订单 | `sal_order.order_no` | `SO202609260004` |
| 打样订单 | `sal_sample_order.order_no` | `SP202609260010` |
| 采购订单 | `pur_purchase_order.po_no` | `PO_…` / `PO_FP_…` |
| 采购申请 | `pur_request.request_no` | `PR-2026-09-14-20` |
| 工单 | `prod_work_order.work_order_no` | `WO20260926000003` |
| 入库单 | `inv_inbound_order.order_no` | `IN_RB_…` / `IN-…` |
| 出库单 | `inv_outbound_order.order_no` | `OUT-20260925-20` |
| 调拨单 | `inv_transfer_order.transfer_no` | `TR202609217692` |
| 盘点单 | `inv_stocktaking.taking_no` | —（**无 `check_no` 列**） |
| 应收单 | `fin_receivable.receivable_no` | `AR-2026-09-14-20` |
| 应付单 | `fin_payable.payable_no` | `AP…` |
| 收款单 | `fin_receipt_record.receipt_no` | `RCP-2026-103` |
| 付款单 | `fin_payment_record.payment_no` | `PAY-2026-09-14-20` |
| 发货单 | `sal_delivery.delivery_no` | `DL-2026-09-14-20` |
| 退货单 | `sal_return.return_no` | `SR-2026-003` |

> ⚠️ 现网存量数据里编号格式并不统一（历史数据混用下划线、横线、纯日期串），**新单按系统生成的走**，不要把旧格式当作规范。前缀与流水位数可在「系统管理 > 单据编号规则」调整。

## 5. 审批与状态流转的通用原则

1. **草稿 → 提交 → 审核**：多数单据走「保存为草稿 → 提交/审核 → 通过/驳回 → （可选）反审核」。审核通过后单据通常不允许直接删除，只能走反审核。
2. **审核不自动改状态字段**：例如调拨单「审批」只写入审批人，不推进 `status`；状态推进发生在**出库（1→2）**与**入库（2→3）**两个动作上。
3. **取消优于删除**：需要作废的单据优先用「取消」（例如退货单 `9=已取消`），保留操作痕迹。
4. **乐观锁冲突**：同一单据被两个人同时编辑时，后保存者会收到「数据已被修改，请刷新后重试」类提示，刷新页面重新进入即可，不会丢数据。

## 6. 常见报错与处理

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| 页面提示「当前账号缺少访问该页面所需的权限」 | 菜单未授权 | 联系管理员在「系统管理 > 角色/菜单」授权 |
| 保存提示 `AE00xx` | 字段级校验失败（必填、重复编码、状态不允许等） | 按提示文案修正后重试；提示未写明时把错误码发给管理员 |
| 操作返回 400 | 业务规则不允许（如已审核单据重复审核、禁用状态被引用） | 先做「反审核/取消」再重新操作 |
| 操作返回 403 | 无权限 / 首次登录未改密 / 接口未被授权 | 联系管理员；首次登录先改密码 |
| 操作返回 500 | 服务端异常（多为接口自身缺陷） | 截图 + 操作时间点报管理员，由运维查日志 |
| 提示「编号已存在 / 生成编号失败」 | 同一秒并发保存 | 稍等重试；连续失败请联系管理员查 `sys_migration`/编号表锁 |
| 页面一直转圈 | 首次访问需编译（开发机冷启动可达数秒） | 等待后刷新；生产环境不会触发 |

## 7. 数据安全提醒（业务用户须知）

- 系统对**软删除**记录保留在库中；越权/误删的恢复由管理员从库层面处理，**不要自行改库**；
- 涉及金额、应收应付的修改建议「谁录入谁修改」，避免权责不清；
- 月末结账、批量反审核等批量操作前，需先做数据备份（[管理员分册 §4 备份与恢复](./07-系统管理员手册.md#4-备份与恢复)）。
