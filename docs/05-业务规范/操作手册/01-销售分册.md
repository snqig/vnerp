# 销售分册（业务用户手册）

> 覆盖模块：`/orders`（销售订单、产品档案、BOM、客户档案）、`/sales`（出货、退货、对帐）、`/crm`（跟进、分析）、`/delivery/vehicles`（车辆）。
> 通用约定（登录、列表操作、单据号、报错处理）见 [00-系统通用说明.md](./00-系统通用说明.md)。

---

## 1. 销售作业全流程图

```
客户建档(/orders/customers)
      ↓
报价/打样(/sales 打样订单)  ← 可选，走打样流程
      ↓
销售订单(/orders/sales) ──保存草稿──→ 提交确认(status 1→2)
      ↓                                    │
      └──────────── 生成工单(/api/workorders) ──→ 状态自动变「部分发货」(3)
                                                        ↓
                                          生产完工 ──→ 订单状态「已完成」(4)
                                                        ↓
                            发货单(/sales/delivery) 1 待发货 → 2 已发货 → 3 已签收
                                                        ↓
                            退货(/sales/return) 1 待审核 → 2 已审核 → 3 已退货（取消则 9）
                                                        ↓
                            对帐单(/sales/reconciliation) + 应收(/finance/receivables)
```

**关键提示**：销售订单的「部分发货(3)」「已完成(4)」**不是业务员点的**，而是由「生成工单」和「工单完工」在后台自动写入的。看到订单自己变成 3/4 属正常，不要手工改状态。

## 2. 客户档案 `/orders/customers`

| 操作 | 入口 | 接口 |
|------|------|------|
| 查询 | 列表页关键字 / 状态筛选 | `GET /api/customers` |
| 新增 | 列表页「新增」→ `/orders/customers/new` | `POST /api/customers` |
| 编辑 | 行内「编辑」 | `PUT /api/customers?id=` |
| 删除 / 批量删除 | 行内 / 勾选后「删除」 | `DELETE /api/customers?id=` |

主要字段：客户编码 `customerCode`、客户名称 `customerName`、客户类型 `customerType`、联络人、联系电话、地址、跟进状态 `followUpStatus`、状态。

> 客户档案是**下游所有单据（订单、发货、退货、应收）的取数来源**。删除客户前请确认没有未结单据，否则历史单据会失去客户归属。

## 3. 产品档案与 BOM

### 3.1 产品档案 `/orders/products`
列：产品编码、产品名称、规格型号、单位、产品分类、BOM 版本、状态。支持点列排序。

| 操作 | 入口 | 接口 |
|------|------|------|
| 新增 / 编辑 | 列表页「新增」 | `POST` / `PUT /api/products` |
| 删除 | 行内 / 批量 | `DELETE /api/products?id=` |
| 查看 BOM | 行内「查看 BOM」 | `GET /api/orders/bom?productCode=` |
| 打印 | 行内「打印」 | 前端 `window.print()`，不打接口 |

### 3.2 BOM（物料清单）`/orders/bom`
列：BOM 编号、产品资讯、版本、状态、物料数量、总成本、创建时间。

明细列：行号、物料编码、物料名称、规格、**用量 `consumption_qty`**、**损耗率 `loss_rate`**、实际用量。

| 操作 | 入口 | 接口 |
|------|------|------|
| 新增 | `/orders/bom/create` | `POST /api/orders/bom` |
| 编辑 | `/orders/bom/edit/{id}` | `PUT /api/orders/bom` |
| 删除 / 批量删除 | 列表页 | `DELETE /api/orders/bom?id=` |
| 审核 | 行内 | `PUT /api/orders/bom {action:'audit'}` |
| 发布 | 行内 | `{action:'publish'}` |
| 停用 | 行内 | `{action:'disable'}` |

> BOM 决定生产领料与成本核算的用量口径。**损耗率 `loss_rate` 就是界面上的「损耗率」**，不是「报废率」。

## 4. 销售订单 `/orders/sales`

### 4.1 列表
顶部统计卡按状态分组，字段：订单编号、客户、下单日期、交货日期、金额、本位币金额、币种、状态、备注；展开行显示订单明细（产品名称、物料编码、数量、单位、单价、金额）。

| 操作 | 入口 | 接口 |
|------|------|------|
| 新增 | 「新增」→ `/orders/sales/new` | `POST /api/orders` |
| 保存草稿 | 表单「储存草稿」 | `POST /api/orders` |
| 提交订单 | 列表「确认订单」（只筛 status=1） | `PUT /api/orders/sales {action:'submit'}` |
| 取消订单 | 行内「取消订单」 | `{action:'cancel'}` |
| 生成工单 | 行内「生成工单」 | `POST /api/workorders` |
| 编辑 | 行内「编辑」（终态 4/5 不可编辑） | `PUT /api/orders` |
| 删除 / 批量删除 | 行内 / 勾选 | `DELETE /api/orders?id=` |
| 导出 / 打印 | 前端实现 | — |

### 4.2 状态机（`sal_order.status`，唯一真相源 `src/lib/order-status.ts`）

| 码 | 中文 | 谁来写 |
|----|------|--------|
| 1 | 待确认 | 新建默认 |
| 2 | 已确认 | 列表「确认订单」（1→2），或同一接口 `action:'approve'` |
| 3 | 部分发货 | **系统自动**：`POST /api/workorders` 建工单时写 |
| 4 | 已完成 | **系统自动**：该订单下所有工单完工后写 |
| 5 | 已取消 | `action:'cancel'`；若已确认(2)，会先校验下游 `inv_outbound_order` 无关联才能取消；3/4 禁止取消，必须走退货 |

**业务规则**
- 终态（4/5）不允许编辑，系统有 `isTerminalSalesOrderStatus` 守卫；
- 已确认(2)可以退回待确认(1)，接口支持 `action:'reject'`，但**列表页没有暴露这个按钮**，需要退回时联系管理员处理；
- 删除不等于作废：删除是软删除（`deleted=1`），要留痕请走「取消」。

### 4.3 销售订单详情 `/sales/orders/{id}`
只读全链路视图，5 个 Tab：

| Tab | 数据来源 | 说明 |
|-----|----------|------|
| 订单明细 | `order.items` | 物料 / 数量 / 单价 / 金额 |
| 发货记录 | `GET /api/sales/delivery?order_id=` | 跳 `/sales/delivery?id=` |
| 退货记录 | `GET /api/sales/return?orderId=` | 跳 `/sales/return?id=` |
| 应收记录 | `GET /api/finance/receivables?sourceNo=` | 收款进度 |
| 物流信息 | 同发货记录 | 物流公司 / 物流单号 / 签收状态 / 发货时间 |

> ⚠️ 这个详情页对「发货/退货」用的是**另一套状态码**（发货 1-5、退货 10/20/30/90），与列表页口径不同，属于历史遗留。以列表页和值对象口径为准。

## 5. 出货管理 `/sales/delivery`

列：出货单号 `delivery_no`、关联订单、客户、出货日期 `delivery_date`、总数量 `total_qty`、总金额 `total_amount`、币种、签收状态 `sign_status`、单据状态 `status`。

### 5.1 新建发货单
弹窗「新建」时：
1. 「关联订单」下拉只显示**已确认(2)**的订单（`GET /api/orders/sales?status=2&pageSize=200`），选中后自动带出客户、收货地址；
2. 填联络人、物流公司、物流单号、发货明细（物料、规格、数量、单价、批号）；
3. 保存 → `POST /api/sales/delivery`。

### 5.2 发货与签收
用同一个「编辑」动作推进状态（PUT `/api/sales/delivery`）：

| 当前状态 | 操作 | 传入 status |
|----------|------|------------|
| 1 待发货 | 点击「发货」 | `2` |
| 2 已发货 | 点击「签收」 | `3` |

### 5.3 状态机（值对象 `src/domain/sales/value-objects/DeliveryStatus.ts`）

```
1 待发货 ──▶ 2 已发货 ──▶ 3 已签收（终态）
   └──────────▶ 9 已取消（终态）        2 也可直接取消
```

**签收状态 `sign_status` 是独立一列**：`0 未签收 / 1 部分签收 / 2 全部签收 / 3 拒收`。
部分签收时系统会同步把 `sign_status` 写成 1。

### 5.4 其他动作
- 查看详情：`GET /api/sales/delivery?id=`；
- 删除 / 批量删除：`DELETE /api/sales/delivery?id=`（注意：已发货/已签收的单建议先取消）；
- 另有扫码发货 `/api/sales/delivery/[id]/ship`、部分发货 `/api/sales/delivery/partial`、重新发货 `/api/sales/delivery/re-ship` 三个接口，供车间/PDA 侧调用。

## 6. 退货管理 `/sales/return`

列：退货单号 `return_no`、关联订单、客户、退货日期 `return_date`、**退货类型 `return_type`**、退货数量、退货金额、币种、检验状态 `inspection_status`、订单状态。

| 动作 | 入口 | 接口 |
|------|------|------|
| 新增 | 列表页「新增」 | `POST /api/sales/return` |
| 编辑 | 行内 | `PUT /api/sales/return` |
| 审批（审核） | 行内「审批」 | `{action:'approve'}` |
| 确认退货 | 行内「确认退货」 | `{action:'complete'}` |
| 取消 | 行内「取消」 | `{action:'cancel'}` |
| 删除 / 批量删除 | 列表页 | `DELETE /api/sales/return?id=` |

状态机：`1 待审核 → 2 已审核 → 3 已退货`，取消则到 `9 已取消`。

辅助枚举：
- 退货类型 `return_type`：`1 品质退货 / 2 数量差异 / 3 规格不符 / 4 其他`
- 检验状态 `inspection_status`：`0 未检验 / 1 检验中 / 2 已检验`

> 已完成(3)／已取消(9) 为终态；退回的货物会自动产生退货入库与红字应收，见财务分册。

## 7. 对帐管理 `/sales/reconciliation`

列：对帐单号、客户、对帐周期（`period_start` ~ `period_end`）、出货金额、退货金额、净额 `net_amount`、已收金额、余额、币种、状态。
明细：类型 `source_type`（1=出货，2=退货）、订单编号、日期、金额。

| 动作 | 入口 | 接口 |
|------|------|------|
| 生成对帐单 | 列表页「生成」 | `POST /api/sales/reconciliation` |
| 按单号重取 | 行内 | `GET /api/sales/reconciliation?id=` |
| 导出 CSV | 前端生成 | — |
| 删除 / 批量删除 | 列表页 | `DELETE /api/sales/reconciliation?id=` |

> ⚠️ **当前限制**：对帐单页**没有「确认/核销」按钮**，也没有对应的状态推进接口，状态无法从「1 草稿」往后走。对帐单目前作为对账结果查询用；如需自动核销，属于待开发项。

## 8. 客户跟进与分析

### 8.1 `/crm/follow` 跟进记录
列：客户名称、跟进方式 `followType`、跟进内容、联络人、业务员 `salesman`、下次跟进日期 `next_follow_date`、商机、状态。
状态下拉：`1 待跟进 / 2 已跟进 / 3 已转化`。统计走 `GET /api/crm/follow/stats`。

### 8.2 `/crm/analysis` 客户分析
列：客户名称、等级 `level`、周期 `period`、订单数、订单金额、退货次数、投诉次数、准时率、满意度、成长率。
操作：新增 / 编辑 / 删除（`POST|PUT|DELETE /api/crm/analysis?id=`），**无审核环节**。

---

## 9. 车辆管理 `/delivery/vehicles`

列：车牌号 `plate_no`、车辆资讯（品牌/型号/颜色）、司机 `driver_name`、里程 `mileage`、状态、保险到期 `insurance_expire`、年检到期 `annual_inspect_expire`。
新增在 `/delivery/vehicles/new`，保存 `POST /api/delivery/vehicles`，删除 `DELETE /api/delivery/vehicles?id=`。

> ⚠️ **已知缺陷**：列表行内的「详情」「维修记录」「费用记录」按钮指向 `/delivery/vehicles/{id}`、`/repair`、`/cost`，这三个页面**目前不存在，点击会 404**。车辆管理当前只能做新增/编辑/删除/查询。

## 10. 销售域常见问答

| 问题 | 说明 |
|------|------|
| 订单自己变成了「部分发货/已完成」 | 正常行为：生成工单写 3，工单完工写 4，无需人工操作 |
| 已确认订单点不了「取消」 | 系统会校验下游出库单；有关联出库必须先去取消出库单，或走退货流程 |
| 发货后想改数量 | 已发货状态下不要直接编辑；先取消发货单，再重新建发货单 |
| 部分的签收怎么理解 | `sign_status=1 部分签收`、`2 全部签收`、`3 拒收`，与单据状态 `status` 是两回事 |
| 对帐单存了但状态不动 | 当前版本对帐单无核销动作，属待开发 |
| 列表里看不到刚删的单 | 删除是软删除，默认不显示；需要找回请联系管理员 |
