# 仓储分册（业务用户手册）

> 覆盖模块：`/warehouse`（入库、出库、调拨、转仓、盘点、库存、批次、质检、设置、库位、库存调整、分切）、`/qrcode`（二维码追溯）。
> 通用约定见 [00-系统通用说明.md](./00-系统通用说明.md)。

---

## 1. 仓储作业全流程

```
采购到货 ──▶ 来料到货通知(/warehouse/inbound/from-po)
              └─▶ 来料检验：合格入库 / 不合格退货
                    └─▶ 生成入库单 / 打印来料二维码 ──▶ 上架

生产完工 ──▶ 生产入库(/warehouse/production-inbound) ──▶ 上架

领料 / 销售出库 ──▶ 出库单(/warehouse/outbound)
                     └─▶ FIFO 批次分配（余料 → 临期 → 入库日期）
                           └─▶ 确认出库（扣减库存）→ 反审核（回退）

调拨 ──▶ 调拨单(/warehouse/transfer)：草稿 → 待审批 → 已出库 → 已入库
盘点 ──▶ 盘点单(/warehouse/stocktaking)：1 待盘点 → 2 盘点中 → 3 待审批 → 4 已审批（9 已取消）
```

---

## 2. 入库管理 `/warehouse/inbound`

列：入库单号 `inbound_no`、供应商、仓库、入库日期、总数量、总金额、状态、创建人。
子页：`/warehouse/inbound`、`/warehouse/inbound/from-po`（来自采购）、`/warehouse/inbound/cutting`（分切入库）、`/warehouse/inbound/channel-inbound`（渠道入库）、`/warehouse/inbound/qrcode`（扫码入库）。

| 操作 | 接口 |
|------|------|
| 列表 / 详情 | `GET /api/warehouse/inbound`、`GET /api/warehouse/inbound/{no}` |
| 添加明细 | `POST /api/warehouse/inbound` |
| 更新、删除 | `PUT`/`DELETE /api/warehouse/inbound` |
| **审核（入库）** | `PUT /api/warehouse/inbound {action:'approve'}` |
| 打印来料条码 | `GET /api/warehouse/inbound/label?no=` |

### 2.1 状态机
`draft 草稿 → pending 待审核 → approved 已审核 → completed 已完成`，另有 `cancelled 已取消`、`rejected 已驳回`。

> ⚠️ **必须「先质检、后入库」**。若把检验结果设为「不合格」，状态会一并变成 `rejected`，此时**审核按钮会置灰无法点击**。不合格品一律走「退货入库」，不要试图审核。

### 2.2 检验状态（`inspection_status`，权威口径）
| 值 | 含义 | 谁能写 |
|----|------|--------|
| 0 | 未检验 | 新建默认 |
| 1 | 检验中 | 质检模块 |
| 2 | 已检验合格 | 质检模块 |
| 3 | 已检验 | **只能由入库单的「审核」动作自动置为 3** |

另外库里还有旧列 `qc_status`（enum `pending/pass/fail/partial`），**以 `inspection_status` 为准**；`partial` 是遗留的无效值。

## 3. 出库管理 `/warehouse/outbound`

列：出库单号、客户、仓库、销售订单号、出库类型、总数量、总金额、状态、创建人。
子页：`/warehouse/outbound`、`/warehouse/outbound/sales-outbound`（销售出库）、`/warehouse/outbound/production-issue`（生产领料出库）、`/warehouse/outbound/other-outbound`（其他出库）。

| 操作 | 接口 |
|------|------|
| 列表 / 详情 | `GET /api/warehouse/outbound`、`GET /api/warehouse/outbound/{no}` |
| 添加明细 | `POST /api/warehouse/outbound` |
| 更新、删除 | `PUT`/`DELETE /api/warehouse/outbound` |
| **确认出库 / 反审核** | `PUT /api/warehouse/outbound {action:'confirm'｜'revert'}` |
| 打印条码 | `GET /api/warehouse/outbound/label?no=` |

**出库的必要前置条件（前端校验）**
1. 出库仓库必须选择；
2. 至少一条明细，且每条明细的 `plan_qty`（计划数量）必须 > 0 且为数字，不能是 `NaN`；
3. 明细的 `allocated_qty`（已分配数量）不能超过该批次可用量；
4. 操作人必须选择。

## 4. FIFO 批次分配（出库必读）

出库不是「减库存总量」，而是**按批次先进先出**扣减。分切入库时直接从批次扣。

**挑选批次优先级**：`余料批次 → 开封批次 → 临期批次 → 入库日期较早的批次`
（`emergencyEmergencyStrategy` 默认按「先到期先出（FEFO）」执行；批次状态为「已耗尽」不参与分配。）

| 页面 | 接口 | 关键字段 |
|------|------|----------|
| 全仓批次列表 | `/api/warehouse/batch/trace`、`/api/warehouse/batch/{id}`、`/{id}/item` | 批次号、物料、仓库、数量、可用量、状态、封存 |
| 分切入库 | `/api/warehouse/inbound/cutting` | 目标批次、目标数量、宽度、长度、总面积、利用率、重量、面积、包装 |
| 分配预览 | 出库明细「分配」列旁「FIFO 分配」按钮 | 按批次列出将消耗的批次与数量 |

**手动指定批次**：在出库明细里直接填「批次号」，走指定批次出库，不参与 FIFO 挑选。

## 5. 调拨与转仓

- `/warehouse/transfer` —— 调拨单：草稿(0) → 待审批(1) → 已出库(2) → 已入库(3)；取消(4)。
- `/warehouse/transfer/child` / `child/inbound` —— 调拨子单（子单提交后自动取数、自动匹配到调出单）。

> ⚠️ **调拨状态机有个反直觉点**：「审批」动作**只写审批人，不推进状态**。状态推进发生在「调出（1→2）」和「调入（2→3）」两个动作上。看到审批后状态还是「待审批」属正常。

## 6. 盘点管理 `/warehouse/stocktaking`

列：盘点单号 `taking_no`、仓库、盘点类型 `taking_type`、盘点日期、总数量、差异数量、状态、创建人。
子页：`/warehouse/stocktaking`、`/warehouse/transfer/stocktaking`（与调拨共用页面）。

状态机：`1 待盘点 → 2 盘点中 → 3 待审批 → 4 已审批`，取消为 `9 已取消`。

| 盘点类型 | 含义 |
|----------|------|
| 1 | 库存盘点（全盘） |
| 2 | 问题复盘（间歇性盘点） |
| 3 | 动态盘点（循环盘点） |
| 4 | 期限盘点（EFEO 临期/短保质期） |

操作：盘点、盘点明细、差异提交、差异确认、差异作废、列表、详情、导出。

> 库里 `inv_stocktaking` **没有 `check_no` 列**，单号列是 `taking_no`；差异相关字段在 `inv_stocktaking_item` 上。

## 7. 库存查询 `/warehouse/inventory`

### 7.1 当前库存
列：物料编码、物料名称、库存数量 `qty`、锁定数量 `locked_qty`、冻结数量 `frozen_qty`、批次、仓库、库位、更新时间。
筛选支持：联系厂商、品牌、规格、分类、是否虚拟。

### 7.2 批次库存
列：物料编码、物料名称、批次号 `batch_no`、仓库 `warehouse_name`、数量 `qty`（总）、可用数量 `available_qty`、锁定数量、状态、生产日期 `production_date`、失效日期 `expiry_date`、物料供应商、备注。
点击「明细」可看批次明细（行号、批次号、数量、状态、备注）。

### 7.3 库存成本
列表 + 汇总 + 明细。支持按物料/仓库复核，导出 Excel。

### 7.4 其他
- `/warehouse/inventory`（库存查询）、`/warehouse/inventory/cost`（库存成本）、`/warehouse/inventory/stock-adjust`（库存调整：调拨、调整、盈亏）；
- `/warehouse/cutting`、`/warehouse/cutting/pieces`（分切计划：双击可加明细；**明细中不可行的行会被标红**）；
- `/warehouse/material-return`、`/warehouse/material-return/input`（退料：退料单号、物料、数量、状态、创建人）；
- `/warehouse/split-order`（拆单：源单号、状态、创建时间）；
- `/warehouse/inbound/cutting`（分切入库）。

## 8. 质检关联 `/warehouse/inbound/qc`

列表列：质检单号 `code`、来源单号 `sourceNo`、供应商名称、物料编码、物料名称、检验数量、合格数量、缺陷数量、检验状态、质检员、检验日期。
接口：`/api/quality/inbound`、`/api/quality/inbound/{id}`、`/{id}/items`、`/{id}/results`、`/api/inventory/inbound/{no}/qc`。
状态：`0 未检验 → 1 检验中 → 2 检验完成`；检验结论 `result`：`pass 合格 / fail 不合格 / pending 待检`。

---

## 9. 仓库设定与库位

- `/warehouse/setup`：仓库列表（编码、名称、地址、负责人、启用），新增/编辑/删除/切换状态；另有「扫码规则」页签（规则名称、类型、规则内容、状态）。
- `/warehouse/locations`：库位列表（库位编码、所属仓库、区域、状态），新增/编辑/删除；按仓库筛选。

## 10. 二维码追溯 `/qrcode`

**二维码类型（9 种）**：`FLOW_CARD 流程卡`、`MATERIAL 物料`、`PRODUCT 产品`、`WORK_ORDER 工单`、`SAMPLE_ORDER 打样单`、`DIE_CUTTING 刀模切割`、`SCREEN_PLATE 网版`、`TOOL 工具`、`OTHER 其他`。
状态：`1 已生成 / 2 已打印 / 3 已使用`（历史遗留 `0 未生成`、`9 已作废`）。

| 页面 / 功能 | 接口 |
|-------------|------|
| 列表、筛选、详情 | `/api/qrcode`、`/api/qrcode/{id}` |
| 新增、更新、批量删除 | `POST`/`PUT`/`DELETE /api/qrcode` |
| 打印（按起止编号批量、补打） | `/api/qrcode/print`、`/api/qrcode/print-list`、`/api/qrcode/single-print` |
| 追溯 | `/api/qrcode/trace`、`/api/qrcode/trace/{type}/{code}` |
| 批量生成 | `/api/qrcode/batch-generate` |
| 统计 | `/api/qrcode/stats`、`/api/qrcode/types` |

「追溯」页看到的是全链路视图：批次 → 物料 → 工单 → 客户，用于**从成品倒查原料、从原料正查成品**。

## 11. 仓储域常见问答

| 问题 | 说明 |
|------|------|
| 入库单点了「审核」没反应 | 检验结果设为不合格时状态是 `rejected`，审核被禁用；不合格品请走退货入库 |
| 出库时提示计划数量无效 | 明细的 `plan_qty` 为空/非数字，补数量后再操作 |
| 想让某个批次优先出库 | 出库明细里手工填「批次号」，走指定批次出库 |
| 调拨审批后状态没变 | 正常：审批只写审批人，状态由调出(→2)、调入(→3)推进 |
| 盘点差异提交后能改吗 | 差异提交后需「差异确认」；作废走「差异作废」 |
| 批次库存里的数量与总量对不上 | 总量含锁定/冻结数量；看「可用量 `available_qty`」才是可分配的 |
| 二维码状态不对 | 状态由「生成(1) → 打印(2) → 使用(3)」动作推进，不要手工改 |
| 分切计划里有些行标红 | 标红行不可行，调整目标数量/宽度后再生成 |
| 删除是软删除吗 | 是（`deleted=1`），列表默认不显示；恢复需管理员处理 |
