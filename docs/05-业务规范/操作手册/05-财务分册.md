# 财务分册（业务用户手册）

> 覆盖模块：`/finance`（应收、应付、收付款、成本、报表）、`/advanced`（成本分析中心、看板）。
> 通用约定见 [00-系统通用说明.md](./00-系统通用说明.md)。

---

## 0. 先看这一节：菜单里能看到什么

财务菜单只挂了 **3 个**页面：

| 路径 | 菜单中文名 |
|------|-----------|
| `/finance/receivable` | 应收款管理 |
| `/finance/cost` | 成本管理 |
| `/finance/report` | 财务报表 |

下面这些路由**存在但没进菜单**，只能直接输 URL 打开（**手册按现状标注，勿向用户承诺**）：

`/finance`（工作台）、`/finance/receivables`、`/finance/receipts`、`/finance/payments`、`/finance/payables`、`/finance/costs`、`/finance/cost-detail`、`/finance/cost-analysis`、`/finance/aging-report`、`/advanced/cost-analysis`、`/advanced/dashboard`

其中 `/finance/receipts`（收款流水）也是个**坏页面**：它请求的 `/api/finance/receipts` 路由不存在，打开会一直加载。查收款请用 `/finance` 工作台。

## 1. 财务单据全景对照

| 中文名 | 表名 | 接口 | 状态机 |
|--------|------|------|--------|
| **应收单** | `fin_receivable` | `/api/finance/receivables` | 1 未收款 → 2 部分收款 → 3 已收款 |
| **应付单** | `fin_payable` | `/api/finance/payable`（仅查询）、`/api/finance/payables`（新增/付款） | 1 未付款 → 2 部分付款 → 3 已付款 |
| **收款单** | `fin_receipt_record` | `/api/finance/receipt` | 无状态字段（凭金额回写应收） |
| **付款单** | `fin_payment_record` | `/api/finance/payment` | 无状态字段（凭金额回写应付） |

单号前缀：应收 `AR`、收款 `RC`、付款 `PM`。

### 应收自动生成的规则
- 来源：`source_type=1`（销售订单），自动生成时 `source_no = 销售订单号`，备注为「销售发货自动生成：{订单号}」；
- 默认到期日 = **下单日 + 30 天**；
- 状态由金额推进：每次收款后 `balance = 应收金额 - 累计收款`，`balance <= 0 → 状态 3`，否则 `2`。

### 应付自动生成的规则
- 来源：`source_type=1`（采购订单）。

> ⚠️ 页面 `receivable` 里有一个 `9 已坏账` 的标签分支，但**代码中没有任何地方写入 status=9**。不要按"坏账"口径使用。

## 2. 应收款管理 `/finance/receivable`

**主功能**：应收单列表 + 逐单核销收款 + 5 张统计卡。

**列表列**：应收单号 `receivable_no`、来源单号 `source_no`、客户 `customer_name`、应收金额 `amount`、已收金额 `received_amount`、余额 `balance`、币种 `currency`、到期日 `due_date`、状态 `status`。

**关键操作**
1. 点行尾「查看详情」→ 弹窗底部出现「确认收款」（**仅当 `balance > 0` 时才会显示**）；
2. 填收款金额、收款日期、收款方式、备注 → 提交 `POST /api/finance/receipt`，body 为 `{ receivable_id, amount, receipt_date, receipt_method, remark }`；
3. 应收单删除：`DELETE /api/finance/receivables?id=`，**状态为「已收款」(3) 时不显示删除按钮**。

状态流转：`1 未收款 →(收款) 2 部分收款 →(收款) 3 已收款（终态）`。

> ⚠️ **已知缺陷**：前端提交的是 `receipt_method`，后端 `recordReceipt()` 读取的是 `receiptMethod`，**字段名不一致 → 收款方式不会入库**。金额、日期、备注正常。对账需要收款方式字段时暂时无法从系统导出。

## 3. 应收汇总 `/finance/receivables`（未上菜单）

只读列表 + 4 张卡：应收总额 / 已收 / 逾期 / 30 天内到期。
列：客户、应收单号、来源单号、应收金额、已收、余额、状态、到期日。「操作」列表头下恒显示"无操作"，是**纯查询页**。

## 4. 应付与付款

### 4.1 `/finance/payables`（未上菜单）
列表列：应付单号 `payable_no`、来源单号 `source_no`、供应商、应付金额 `amount`、已付 `paid_amount`、余额 `balance`、币种、到期日、状态。
操作：行内「付款」按钮（**仅 `status !== 3` 显示**）→ 弹窗填金额 / 付款方式 / 付款日期 → `POST /api/finance/payables/{id}/payment`。

### 4.2 `/finance/payments`（未上菜单）
付款流水只读列表：付款单号、供应商、付款方式、关联应付单号、付款日期。无新增/删除。

### 4.3 `/finance` 工作台（未上菜单）
应收/应付/收款/付款四合一 Tab，顶部 4 张 KPI 卡。

> ⚠️ **已知缺陷**：在这个页面上「新增应付」和「删除应付」打到的是 `/api/finance/payable`，而该路由**只有 GET**，这两个操作**必然失败**。请改用 `/finance/payables` 页做新增。

## 5. 成本管理

### 5.1 `/finance/cost`【菜单：成本管理】
成本记录列表 + 汇总 + 批量删除。
列：成本类型 / 单据号 `cost_no`、来源类型 `source_type`、关联单号 `order_no`、部门、金额 `amount`、成本日期 `cost_date`、摘要、状态。
成本类型：`material 材料 / labor 人工 / overhead 制造费用 / outsource 外协 / other 其他`。
> 金额以「元」为单位存储，不要再做 /100。
「状态」接口有返回但页面未展示，其取值与含义待确认，**不要拿它做报表口径**。

### 5.2 `/finance/costs`（未上菜单）按工单成本核算
列：工单号、计划数量、完工数量、材料成本、人工成本、制造费用、总成本、单位成本、核算时间。
点「核算」→ `POST /api/finance/costs { workOrderId }`，系统用 `calculateWorkOrderCost()` 计算并写入（`work_order_costs` 表）。

### 5.3 `/finance/cost-detail`（未上菜单）
按工单 + 成本类型查看成本明细：单号、工单号、成本类型、金额、币种、日期、摘要。
接口同 `/api/finance/costs`。

## 6. 成本分析

### 6.1 `/finance/cost-analysis`（未上菜单）
读 `fin_cost_record` + `sys_config`，按 `cost_date` 的「年-月」聚合（材料 / 人工 / 制造费用 / 外协 / 合计），预算取自 `sys_config` 的 `finance.budget_monthly`。
- 4 张卡：本月成本 / 上月成本 / 环比变化 / **预算执行率（>100% 标红「超预算」）**
- 图表：本月 vs 去年同期折线 + 四类成本占比饼图
- **用户看点**：成本趋势、成本结构、是否超月度预算

### 6.2 `/advanced/cost-analysis`（未上菜单，页面名「成本分析中心」）
- `profit-analysis`：查 `sal_order_item`，给出收入 / 直接成本 / 期间费用 / 毛利 / 净利率
- `abc-classification`：查 `inv_inventory`，给出 A/B/C 类物料分布
- 毛利率 < 20%、净利率 < 10% 会标红
- **用户看点**：哪款产品不赚钱、哪些物料占了资金

## 7. 财务报表 `/finance/report`

- 周期支持：日 / 周 / 月 / 季 / 年（`period_type`）
- 5 张卡：本月收入 / 本月支出 / 应收总额 / 应付总额 / 本月利润
- 收支明细列：周期、类型、科目、收入、成本、利润、利润率
- 支持导出（前端导出，非后端接口）

## 8. 账龄分析

> ⚠️ **当前页面是坏的**：`/finance/aging-report` 请求 `/api/finance/receivable-aging` 与 `/api/finance/payable-aging`，**这两个路由并不存在**，打开会永远空白。
> 真实实现只有 `/api/finance/aging?type=`，可用接口手动访问查看。口径为：`status != 3 且 balance > 0`，账龄分 7 段：已到期 / 1-30 / 31-60 / 61-90 / 91-180 / 181-365 / 366+。

## 9. 财务域常见问答

| 问题 | 说明 |
|------|------|
| 应收单余额一直不减少 | 收款用「查看 → 确认收款」入口，直接改金额不会回写余额 |
| 已收款的单不能删除 | 正常：状态 3 是终态 |
| 收款方式保存后查不到 | 已知缺陷（字段 `receipt_method` vs `receiptMethod`），金额不受影响 |
| 在 `/finance` 新增应付报错 | 已知缺陷：该路由无 POST；请到 `/finance/payables` 操作 |
| 应付余额怎么推进到「已付款」 | 走付款动作，系统按 `paid_amount` 比对自动置 3 |
| 应付单号为什么是 AP… 前缀 | 与应收 `AR`、收款 `RC`、付款 `PM` 一样是代码硬编码前缀 |
| 成本数据不是我录入的 | `/finance/cost` 是人工成本记录；`/finance/costs` 是按工单自动核算，两者不要混用 |
| 想看超预算 | 去 `/finance/cost-analysis`，预算执行率 > 100% 会标红 |
| 账龄分析页打开是空的 | 已知缺陷：路由不存在，等后续修复 |
| 财务报表能导出发票吗 | 不能，导出的是收支明细表格，不含发票 |
