## 0. 先看这一节：质量模块都在哪

| `/quality/process` | 工艺监察 | 关键工序（印刷/复合/熟化/分切）抽样检验 |

## 2. 来料检验 `/quality/incoming`（最关键的一类）

列：检验单号、供应商、物料编码、物料名称、来料数量、检验数量、合格数量、不合格数量、检验结论、检验员、检验日期。

| 动作 | 接口 |
|------|------|
| 列表 / 详情 | `/api/quality/incoming`、`/api/quality/incoming/{id}` |
| 新增、编辑 | `POST` / `PUT /api/quality/incoming` |
| 删除 / 批量删除 | `DELETE /api/quality/incoming?id=` |
| 明细 | `/api/quality/incoming/{id}/items` |
| 检验结果 | `/api/quality/incoming/{id}/results`、`/api/quality/incoming/{id}/result` |
| 引用来源 | `/api/inventory/inbound/{no}/qc` |
| 统计 | `/api/quality/incoming/stats` |

### 2.1 检验结论 `result` 的取值（权威口径）
| 值 | 含义 |
|----|------|
| `pass` | 合格 |
| `fail` | 不合格 |
| `pending` | 待检 |

> ⚠️ 早期版本里曾用 `reject` / `qualified` / `unqualified` 等写法，那些值**永远不会命中**业务分支。以 `pass / fail / pending` 为准。

### 2.2 检验结论如何直接影响库存（必读）
1. 结论写 **合格 `pass`** → 对应批次**解冻**（`frozen = 0`），并让关联入库单的 `inspection_status` 变为 `1`；
2. 结论写 **不合格 `fail`** → 批次**冻结**（`frozen = 1`），入库单 `inspection_status` 变为 `2`；
3. 入库单的 `inspection_status=3`（已检验）**只能由入库单自身的「审核」动作置位**，质检侧不能写；
4. 冻结的批次不参与 FIFO 分配，因此**不合格来料不会流进生产**。

> 这就是质检与仓储的咬合点：**不检验，批次就是冻结的**。

## 6. 不合格品处理 `/quality/unqualified-product`

**主功能**：登记不合格品 → 指派处理人 → 做处理决定 → 处理完成，形成闭环。

状态机（值对象 `src/domain/quality/value-objects/UnqualifiedStatus.ts`）：

```
1 pending   待处理（新建默认）
    ↓ 指派处理人 / 做处理决定
2 handling  处理中
    ↓ 处理完成
3 completed 已完成
```

列：处理单号 `record_no`、关联工单号、批次号、产品、缺陷类型、缺陷描述、数量、原因、处理方式、处理人、状态、创建时间。
接口：`/api/quality/unqualified`、`/api/quality/unqualified/stats`、`/api/quality/unqualified/counts`，操作：新增 / 编辑 / 删除 / 上拉刷新。

## 12. 质量域常见问答

| 问题 | 说明 |
|------|------|
| 入库时批次被冻结，怎么办 | 走来料检验，结论选「合格 `pass`」后批次自动解冻 |
| 检验结论选了不合格，入库单还能审核吗 | 不能：不合格时入库单状态是 `rejected`，审核按钮置灰；应走退货入库 |
| 检验状态显示「已检验」是谁写的 | 入库单自己的「审核」动作，质检侧改不了 |
| 不合格品卡在「待处理」 | 需要先指派处理人并做处理决定，状态才会到 2 |
| 检验单号为什么是自动生成 | 系统按单据类型自动编号，不允许手填 |
| 想补录历史检验数据 | 用「新增」补一条即可，注意检验日期填真实日期 |
| 客诉里的「严重程度」怎么定 | 按对企业的影响程度（涉及批量退货/停线的算高） |
| 检验项目在哪里维护 | 在 `/quality/inspection-items`（未上菜单，直接输 URL） |
| SPC 页面数据全中文 | 已知问题：SPC 模块未国际化 |
