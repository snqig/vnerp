## 1. 升级前准备

### 1.1 检查清单

- [ ] 确认升级版本号
- [ ] 备份数据库
- [ ] 备份代码
- [ ] 通知所有用户
- [ ] 安排升级窗口（建议凌晨低峰期）

### 1.2 备份操作

```bash
# 1. 备份数据库
mysqldump -u root -p vnerpdacahng > backup_before_upgrade_$(date +%Y%m%d).sql

# 2. 备份代码
cp -r /path/to/erp-project /path/to/erp-project-backup
```

## 2. 升级步骤

### 2.1 标准升级流程

```bash
# 1. 停止服务
pm2 stop all

# 2. 拉取最新代码
git pull origin main

# 3. 安装依赖
npm install

# 4. 执行数据库迁移（如有）
npm run db:migrate

# 5. 构建
npm run build

# 6. 启动服务
pm2 start all

# 7. 验证服务正常
curl http://127.0.0.1:5000/api/health
```

## 3. 数据迁移

### 3.1 迁移脚本

如有数据库结构变更，执行迁移脚本：

```bash
# 执行迁移
npx drizzle-kit push

# 或手动执行 SQL
mysql -u root -p vnerpdacahng < migration.sql
```

### 3.2 数据修复脚本

如升级后需要修复数据，运行：

```bash
# 库存重算
curl -X POST http://127.0.0.1:5000/api/warehouse/inventory/recompute
```

## 4. 回滚方案

### 4.1 代码回滚

```bash
# 1. 停止服务
pm2 stop all

# 2. 回滚代码到上一版本
git reset --hard <previous_commit_hash>

# 3. 重新安装依赖
npm install

# 4. 重新构建
npm run build

# 5. 启动服务
pm2 start all
```

### 4.2 数据回滚

```bash
# 1. 停止服务
pm2 stop all

# 2. 恢复数据库
mysql -u root -p vnerpdacahng < backup_before_upgrade_20260926.sql

# 3. 启动服务
pm2 start all
```

**注意**：数据回滚会丢失升级后产生的所有数据！
