## 3. 数据库设计

### 3.1 命名规范

- 表名：小写下划线，按模块前缀
  - `inv_` - 仓储库存
  - `prod_` - 生产
  - `sal_` - 销售
  - `pur_` - 采购
  - `fin_` - 财务
  - `hr_` - 人力资源
  - `sys_` - 系统设置

- 字段名：小写下划线
  - 主键：`id`（自增）
  - 外键：`xxx_id`
  - 时间：`create_time`, `update_time`
  - 软删除：`deleted`（0=正常, 1=已删除）

### 3.2 核心表

| 表名 | 说明 |
|---|---|
| inv_inventory | 库存汇总表 |
| inv_inventory_batch | 库存批次表（权威明细） |
| inv_inbound_order | 入库单 |
| inv_outbound_order | 出库单 |
| sal_order | 销售订单 |
| prod_work_order | 生产工单 |
| pur_order | 采购订单 |

### 3.3 库存双轨机制

- **批次表（inv_inventory_batch）**：权威明细，所有出入库都操作批次表
- **汇总表（inv_inventory）**：派生汇总，通过 recomputeInventorySummary() 从批次表重算

**重要原则**：不要直接修改汇总表，应该操作批次表后调用重算函数。

## 4. API 规范

### 4.1 统一响应格式

```typescript
// 成功
{
  code: 200,
  success: true,
  message: '操作成功',
  data: {...}
}

// 分页
{
  code: 200,
  success: true,
  message: '查询成功',
  data: {
    list: [...],
    total: 100,
    page: 1,
    pageSize: 20
  },
  pagination: {...}
}

// 失败
{
  code: 400,
  success: false,
  message: '错误信息'
}
```

### 4.2 路由规范

- 路径：`/api/模块/资源`
  - `/api/warehouse/inbound` - 入库单
  - `/api/warehouse/batch` - 批次库存

- HTTP 方法：
  - GET - 查询列表/详情
  - POST - 创建
  - PUT - 更新
  - DELETE - 删除

### 4.3 权限控制

使用 `withPermission` 装饰器：

```typescript
export const GET = withPermission(
  async (request, user) => {
    // 业务逻辑
  },
  { permission: 'warehouse:inbound:list' }
);
```

## 5. 前端规范

### 5.1 页面结构

每个模块页面统一结构：
1. 统计卡片区域（StatsCards）
2. 工具栏（搜索、筛选、新建按钮）
3. 表格列表
4. 分页
5. 新建/编辑对话框

### 5.2 统计卡片

统一使用 `StatsCards` 组件：

```tsx
<StatsCards
  configs={[
    { key: 'total', label: '总数', icon: Icon, ...StatsTheme.blue },
  ]}
  stats={[
    { key: 'total', count: 100 },
  ]}
/>
```

### 5.3 国际化

- 所有文本使用 `useTranslations`
- 不要硬编码中文
- key 命名：`模块.功能.字段`

## 8. 常见问题

### Q1：数据库连接失败？

**A**：检查 `.env.local` 中的数据库配置是否正确。

### Q2：页面显示国际化 key？

**A**：检查 messages/zh-CN.json 中是否有对应的 key。

### Q3：库存数据不一致？

**A**：调用 `/api/warehouse/inventory/recompute` 重新计算汇总表。
