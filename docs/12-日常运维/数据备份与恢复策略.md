# 数据备份与恢复策略

> **版本**：v1.0
> **更新日期**：2026-09-26

---

## 一、备份策略

### 1.1 备份频率

| 备份类型 | 频率 | 保留时间 | 说明 |
|---|---|---|---|
| 全量备份 | 每天凌晨 2:00 | 30 天 | 完整数据库备份 |
| 增量备份 | 每 6 小时 | 7 天 | 只备份变化的数据 |
|  binlog 备份 | 实时 | 7 天 | 用于精确到秒的恢复 |

### 1.2 备份内容

| 内容 | 说明 |
|---|---|
| 数据库 | MySQL 全量备份 |
| 上传文件 | 用户上传的图片、文档等 |
| 配置文件 | .env、配置文件等 |
| 日志文件 | 应用日志、错误日志 |

### 1.3 备份存储

| 存储位置 | 说明 |
|---|---|
| 本地磁盘 | /backup/mysql/ |
| 异地备份 | 每周拷贝到另一台服务器 |

## 二、恢复流程

### 2.1 恢复场景

| 场景 | 恢复方式 | 预计耗时 |
|---|---|---|
| 误删单条数据 | 从 binlog 恢复 | 5 分钟 |
| 误删整表 | 从昨天全量备份恢复 | 30 分钟 |
| 数据库损坏 | 从最近全量 + binlog 恢复 | 1 小时 |
| 服务器故障 | 新服务器部署 + 恢复备份 | 4 小时 |

### 2.2 恢复步骤

1. **确认故障范围**：哪些数据丢了？什么时候丢的？
2. **选择备份点**：全量备份 + binlog 恢复到指定时间点
3. **恢复到临时库**：先恢复到测试库，验证数据正确
4. **切换到生产**：确认无误后切换到生产库
5. **验证业务**：验证核心功能正常

## 三、监控告警

### 3.1 监控指标

| 指标 | 警告阈值 | 严重阈值 |
|---|---|---|
| CPU 使用率 | > 70% | > 90% |
| 内存使用率 | > 75% | > 90% |
| 磁盘使用率 | > 80% | > 95% |
| 数据库连接数 | > 80% | > 95% |
| API 错误率 | > 1% | > 5% |
| API 响应时间 P95 | > 500ms | > 2000ms |

### 3.2 告警方式

| 级别 | 方式 | 接收人 |
|---|---|---|
| 警告 | 邮件 | 运维人员 |
| 严重 | 短信 + 电话 | 技术负责人 |

## 四、降级策略

### 4.1 降级原则

**核心业务优先**：
- ✅ 必须保证：入库、出库、销售、生产工单
- ⚠️ 可以降级：统计报表、AI 预测、数据分析

### 4.2 降级方案

| 场景 | 降级方式 |
|---|---|
| 数据库慢查询 | 非核心报表延迟加载 |
| Redis 缓存挂了 | 直接查数据库（慢一点但能用） |
| 文件服务挂了 | 上传功能暂停，不影响业务操作 |
| 短信服务挂了 | 告警改邮件通知 |
