# 灰度发布方案

> **版本**：v1.0
> **更新日期**：2026-09-26

---

## 一、发布流程

### 1.1 发布阶段

| 阶段 | 流量比例 | 验证时间 | 说明 |
|---|---|---|---|
| 内部测试 | 0% | 1 天 | 开发、测试团队内部使用 |
| 小范围试用 | 10% | 2 天 | 选 1-2 个部门试用 |
| 扩大范围 | 50% | 2 天 | 一半用户使用新版本 |
| 全量发布 | 100% | - | 所有用户使用新版本 |

### 1.2 回滚条件

出现以下情况立即回滚：
- ❌ 核心功能报错（入库、出库、登录）
- ❌ 错误率 > 5%
- ❌ 响应时间 P95 > 2 秒
- ❌ 数据不一致

---

## 二、发布前检查清单

### 2.1 代码检查

- [ ] 所有测试通过
- [ ] 代码审查完成
- [ ] 无 console.log 调试代码
- [ ] 无硬编码的测试数据

### 2.2 数据检查

- [ ] 数据库迁移脚本已备份
- [ ] 回滚脚本已准备好
- [ ] 测试环境已验证

### 2.3 监控检查

- [ ] 监控告警已配置
- [ ] 回滚方案已准备
- [ ] 值班人员已安排

---

## 三、回滚方案

### 3.1 代码回滚

```bash
# 回滚到上一个版本
git checkout previous-tag
npm run build
pm2 restart all
```

### 3.2 数据回滚

```bash
# 如果数据库有变更，需要执行回滚脚本
mysql -u root -p vnerp < rollback.sql
```

---

## 四、发布后观察

### 4.1 观察指标

| 指标 | 正常范围 | 异常处理 |
|---|---|---|
| 错误率 | < 1% | > 5% 立即回滚 |
| 响应时间 P95 | < 500ms | > 2000ms 考虑回滚 |
| CPU 使用率 | < 70% | > 90% 扩容或回滚 |
| 内存使用率 | < 75% | > 90% 扩容或回滚 |

### 4.2 观察时长

- 发布后 1 小时：重点观察
- 发布后 24 小时：持续观察
- 发布后 3 天：确认稳定
