## 四、产品缺陷修复明细（含文件定位与验证）

### 1. `UserInfo` 无 `id` 字段，6 处误写 `userInfo?.id` → 操作人 ID 恒 `undefined`
- 真实定义：`src/lib/api-permissions.ts` 的 `UserInfo` 只有 `userId`（全仓 98 处用 `userId`）。
- 修复：6 处 `userInfo?.id` → `userInfo?.userId`（含工装报废 `scrap_by`）。
- 验证：全仓正则复核 **0 残留**；`tests/e2e/dcprint-tool-lifecycle.spec.ts` **7/7 通过**。

### 2. `MysqlSampleOrderRepository.save()` INSERT 列数与占位符不匹配 → 打样单创建 100% 失败
- 定位：`src/infrastructure/repositories/MysqlSampleOrderRepository.ts` — 31 列 vs 30 值。
- 修复：`VALUES` 补 1 个占位符（19 `?` + `NOW()` + 11 `?` = 31）。
- 验证：`tests/e2e/sample-to-order.spec.ts` 由多例 skip/失败 → **11/11 通过**。

### 3. DB 边界参数归一化缺失（`src/lib/db/index.ts`）
文件注释早已声明「`undefined` 应在预处理前替换为 `null`」，但 `execute()`/`query()` **从未实现**；同时缺少 ISO-8601 → MySQL DATETIME 的归一。
- 影响：可选字段未传 → 写入接口 400/500；`2026-09-14T08:19:44.911Z` 直写 DATETIME 列 → errno 1292 → **打样转大货 100% 失败**。
- 修复：新增 `normalizeSqlValues()`（`undefined → null`）与 `normalizeIsoDatetime()`；**`transaction()` 用 Proxy 包装连接**，使事务内 `conn.execute/query` 同样归一化（此前是明确的绕过口，正是它导致 `convertOrder` 失败）。
- 遗留提示：`src` 下近 300 处 `toISOString()` 属同类风险，本次在 DB 边界统一兜住，无需逐处改。

### 4. BUG-005：登录页 3 个 401（`AuthGate` 短路）
- 溯源（探针实测）：`GET /api/system/config?pageSize=200` ×2（`useCompanyName` + `SystemConfigInitializer`）、`GET /api/organization?type=company` ×1（`useCompanyName`）。
- 关键约束：`access_token` / `refresh_token` 是 **httpOnly**（`src/app/api/auth/login/route.ts:401-413`）→ 客户端 JS 读不到，不能用 `document.cookie` 判定登录态。
- 修复：`src/contexts/AuthContext.tsx` 新增 `useAuthGate(): 'no-provider' | 'pending' | 'authenticated' | 'anonymous'`（不抛错，且区分「未解析」与「已解析为未登录」）；`useCompanyName` 与 `SystemConfigInitializer` 在 `pending` 等待、`anonymous` 短路。
- **行为等价性**：原先请求 401 后也是回退 i18n 默认名，故 UI 结果不变，仅消除噪音。
- 验证：
  - 未登录 `/zh-CN/login` → **0 个 4xx/5xx、0 个 console.error**；
  - 登录后 `/dashboard` → `/api/system/config?pageSize=200` **200**（公司名/配置照常生效）；
  - `src/hooks/useCompanyName.test.ts` **8/8 通过**（`no-provider` 分支保留原行为，未破坏单测契约）。

### 5. `prod_work_order` 无 `plan_qty` 列（真名 `quantity`）→ 两个接口恒 500
- 定位：`material-issue`、`production-inbound` 直接 SELECT `plan_qty` → errno 1054。
- 修复：改查 `quantity`（保持对外别名 `plan_qty`，与 finance/cost-variance 既有口径一致）。
- 同步修正同类静默缺口：`dcprint/ink-query`、`production/orders`、`init/data-logic`。

### 6. `production-inbound` 工单状态机按数值比较
- 定位：`wo.status < 50` 对 varchar 的 `'confirmed'` 恒 false（NaN 比较）→ 状态永不流转；原实现还会把数值写进 varchar 列。
- 修复：改为字符串状态机（`WO_ACTIVE_STATUSES`）。

### 7. `init/data-logic` 两个视图定义引用不存在的表/列 → 恒静默失败
`safeCreateTable` 把 DDL 异常 catch 掉只 push 进 `results`，因此错误 SQL 不会中断初始化、只会让视图永远建不出来。
- `v_purchase_to_inbound`：`pur_order` → 真名 `pur_purchase_order`；`po.order_no` → 真名 `po_no`；`io.purchase_order_id` → 真名 `io.po_id`。
- `v_workorder_to_outbound`：`wo.sales_order_id` / `wo.sales_order_no` / `wo.plan_qty` → 真名 `order_id` / `order_no` / `quantity`（连带 JOIN 条件改 `so2.order_id = wo.order_id`）。
- 验证：修正后 SQL 均以 `SELECT * FROM (<sql>) AS x LIMIT 0` 在活库校验通过。
