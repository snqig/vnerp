# /dashboard/ceo 国际化修复清单（2026-09-04）

## 根因
CEO 驾驶舱页面 `src/app/[locale]/dashboard/ceo/page.tsx` 全部文本走 `useTranslations('Dashboard')` + `ts('k_xxxxxx')`。
但 i18n codemod（i18n-codemod-common.mjs）**只生成了机器 key、没把翻译值写入 messages 文件**——
以下 10 个 key 在 `messages/{zh-CN,en,vi,zh-TW}.json` 的 `Dashboard` 命名空间**完全缺失**。

按 `src/i18n/request.ts` 与 `src/components/IntlProvider.tsx` 的 `getMessageFallback` 配置，
缺失 key 会**原样渲染成 `Dashboard.k_xxx`** 字符串 → 页面上能看到 key 而非中文，即"国际化有问题"。

> 说明：访问 `http://localhost:5000/dashboard/ceo` 无 locale 前缀是正常的——`[locale]`=`dashboard` 不在 locales 列表，next-intl 自动 fallback 到 `defaultLocale`(zh-CN)，页面能正常渲染，这不是本次 bug 的根因。

## 验证
- 自写诊断脚本比对页面 `ts()/tc()` 用到的 key 与 4 语言 `Dashboard`/`Common` 命名空间 → **0 missing**。
- 4 个 messages 文件 `JSON.parse` 均合法（脚本保留原 CRLF 缩进，diff 仅 Dashboard 块新增 10 行）。
- `Common` 命名空间 3 个 key（qualityPassRate/fault/noData）本就齐全，无需改动。

## 生效方式
dev server 在运行时，**硬刷新**浏览器即可（next-intl 多数情况热重载 messages）。
若页面仍显示 `Dashboard.k_xxx`，说明 messages 被缓存，需重启 dev：`npm run dev`（`-p 5000` 已内置脚本，勿重复写端口），必要时清 `.next` 缓存。

## 同类风险排查建议（未做）
此 bug 是 codemod 漏写翻译的个例，其他页面可能也有同类缺失。可跑既有全量诊断工具：
```
node scripts/debug-perf/diagnose_i18n_keys.mjs src/app/[locale]
```
默认只扫 sample / production/workorder，传 `src/app/[locale]` 可扩到全站，输出所有缺失 key 及文件位置。
