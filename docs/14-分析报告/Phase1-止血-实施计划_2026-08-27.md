## 2. R4 — 消除 `inv_inventory` 的 SELECT→INSERT 竞态（P0）

### 2.1 根因
`uk_material_warehouse (material_id, warehouse_id)` **不含 `deleted`**。软删行仍占唯一键。
"先 `SELECT ... WHERE deleted=0` 再 `INSERT`" 在并发/遇软删行时会撞 `Duplicate entry for key uk_material_warehouse` → 整事务回滚 → 进死信。已发生过的案例见路线图 R4。

### 2.2 改造点 A：`recomputeInventorySummary` 孤儿补建（`inventory-ledger.ts:133-149`）
当前先 SELECT `i.id IS NULL` 再 INSERT，非原子。

**改为**：探测列先不改；把 INSERT 换成 `INSERT ... ON DUPLICATE KEY UPDATE`（幂等复活/累加），并删掉"若 affectedRows>0 则 return"的前置 UPDATE 分支依赖——统一走"UPSERT 优先，无行则补建"的单一路径：

```ts
// inventory-ledger.ts  ~133
const [updRes] = await conn.execute(
  `INSERT INTO inv_inventory (
     material_id, material_code, material_name, warehouse_id, warehouse_name,
     quantity, available_qty, area, batch_no, locked_qty, unit, version, create_time, update_time, deleted
   ) VALUES (?, ?, ?, ?, ?, ?, ?, ?, NULL, 0, ?, 0, NOW(), NOW(), 0)
   ON DUPLICATE KEY UPDATE
     material_code = VALUES(material_code),
     material_name = VALUES(material_name),
     warehouse_name = VALUES(warehouse_name),
     unit = VALUES(unit),
     version = COALESCE(i.version, 0) + 1,
     deleted = 0,
     update_time = NOW()`,
  [r.material_id, r.material_code, r.material_name, r.warehouse_id, r.warehouse_name, r.q, r.a, r.area, r.unit]
);
```
> 注意：UPSERT 的 `ON DUPLICATE` 分支里 `i.version` 引用需确保表别名；本函数仅在"孤儿补建"语义调用，实际命中重复键即视为行已存在→复活即可，无需再 SELECT。为稳妥，保留上方"已存在则 UPDATE"分支作为第一优先路径不变，**仅把下方孤儿 INSERT 改为 UPSERT** 即可消除竞态（两路径二选一，互不冲突）。

### 2.3 改造点 B：`adjustInventory` 新建分支（`inventory-sync.ts:163-184`）
当前 `inventoryRows.length === 0` 时 `INSERT`，并发下两事务同时 SELECT 空→双 INSERT 撞键。

**改为**：把该分支 INSERT 改为 UPSERT，并据 `affectedRows`/是否存在决定 `beforeQty`：

```ts
// inventory-sync.ts  ~178（替换原 INSERT 分支）
const [insRes]: Loose = await txConn.execute(
  `INSERT INTO inv_inventory (
     material_id, warehouse_id, batch_no, quantity, locked_qty, available_qty, version
   ) VALUES (?, ?, ?, ?, 0, ?, 1)
   ON DUPLICATE KEY UPDATE
     quantity = quantity + VALUES(quantity),
     available_qty = available_qty + VALUES(available_qty),
     version = version + 1`,
  [materialId, warehouseId, batchNo || null, quantity, quantity]
);
// UPSERT 命中既有行时，beforeQty 需重新读取；否则为 0
const [reChk]: Loose = await txConn.execute(
  `SELECT id, quantity, available_qty, version FROM inv_inventory
   WHERE material_id = ? AND warehouse_id = ? AND deleted = 0 FOR UPDATE`,
  [materialId, warehouseId]
);
const inv = reChk[0];
inventoryId = inv.id;
beforeQty = parseFloat(inv.quantity) - quantity;          // 当前量 - 本次增量
beforeAvailableQty = parseFloat(inv.available_qty) - quantity;
```
> 这样既消除撞键回滚，又保持 `beforeQty` 语义正确（新建行 before=0；并发复活行 before=扣减前量）。

## 3. R5 — 统一 `inv_inventory_log` 三态 INSERT 为单一契约（P1）

| `change_type`（遗留） | warehouse_id, material_id, change_type, change_qty, order_no, remark, create_time | `transfer/[id]/outbound/route.ts:103`、`transfer/[id]/inbound/route.ts:127`、`stocktaking/route.ts:237`、`init/seed-data/route.ts:439` |

### 3.2 Canonical 契约决策
选定 **`operation_type` 形态为 canonical**（理由：核心业务流 adjust/lock/unlock/split 已用；`getInventoryLogs` 已按 `operation_type` 出 label；列最全）。
为**不丢数据**，helper 同时填充 `trans_type/quantity/source_type/source_no`（与 operation_* 语义对齐映射），使 `inventory/route.ts` 等 trans 形态日志也能被统一查询。

映射规则：
- `operation_type` 1入/2出/3损耗/4调拨/5报废/6锁定/7解锁
- `trans_type` ← in/out/adjust/transfer/scrap（lock/unlock 归为 adjust）
- `source_type/source_no` ← `business_type/business_no`
- `quantity/operation_qty` ← 同值
- `before_qty/after_qty` ← 同值

### 3.3 统一 helper（新增 `src/lib/inventory-ledger.ts`）
```ts
export interface InventoryLogInput {
  materialId: number;
  warehouseId: number;
  batchNo?: string | null;
  operationType: number;           // 1..7
  operationQty: number;
  beforeQty?: number | null;
  afterQty?: number | null;
  businessType?: string | null;    // → source_type
  businessNo?: string | null;      // → source_no
  transType?: 'in'|'out'|'adjust'|'transfer'|'scrap'|null;
  unit?: string | null;
  remark?: string | null;
  operatorId?: number | null;
}
const OP_TO_TRANS: Record<number,string> = {1:'in',2:'out',3:'adjust',4:'transfer',5:'scrap',6:'adjust',7:'adjust'};
export async function appendInventoryLog(conn, i: InventoryLogInput): Promise<void> {
  await conn.execute(
    `INSERT INTO inv_inventory_log (
       material_id, warehouse_id, batch_no,
       operation_type, operation_qty, trans_type, quantity,
       before_qty, after_qty, unit,
       source_type, source_no, business_type, business_no,
       remark, operator_id, create_time
     ) VALUES (?,?,?,?,?,?,?,?,?,?,?,?,?,?,?,?,NOW())`,
    [i.materialId, i.warehouseId, i.batchNo ?? null,
     i.operationType, i.operationQty, OP_TO_TRANS[i.operationType] ?? 'adjust', i.operationQty,
     i.beforeQty ?? null, i.afterQty ?? null, i.unit ?? null,
     i.businessType ?? null, i.businessNo ?? null, i.businessType ?? null, i.businessNo ?? null,
     i.remark ?? null, i.operatorId ?? null]
  );
}
```
