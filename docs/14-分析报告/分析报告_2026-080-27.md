## 三、工单状态机（核心）
```

draft（草稿）
│ approve()
▼
approved（已审核）
│ start() / markPicking() / issueMaterials()
▼
picking / in_progress（领料中 / 生产中）
│ complete(qty)
▼
completed（已完工）
│ close()
▼
closed（已结案）

任意节点 → cancelled（作废）

**text**

```

**关键业务规则**

| 操作 | 条件 | 副作用 |
|------|------|--------|
| create | productId>0, plannedQty>0 | 状态 draft，可带物料需求 |
| approve | 状态允许审核 | → approved |
| start | 状态允许开工 | → in_progress，记 actualStartDate |
| issueMaterials | 状态 approved/picking/in_progress | 校验物料在 BOM 内，累加已领量，发事件 |
| complete | 状态允许完工 | completedQty 累加，**禁止超计划**，记 actualEndDate |
| close | 状态允许结案 | → closed |
| cancel | 状态允许作废 | → cancelled |

**完工超限硬校验**：
$$ \text{completedQty}_{old} + \text{本次} \le \text{plannedQty} $$
否则抛出 `DomainError`。

## 四、子单据逻辑

### 1. 领料单（PickOrder）
- 绑定工单 + 物料行
- 状态：创建 → 审核 → 取消
- 审核后 FIFO 扣库存（`fifo-allocation`）
- 超领校验：已领 + 本次 ≤ 需求 × 允许系数

### 2. 报工（WorkReport）
- 关联工单、工序、数量、工时、不良
- 状态：创建 → 审核 → 取消
- 印刷/模切等可写工具列（网版、刀模寿命等，Handler 同步）

### 3. 完工单（FinishOrder）
- 完工数量 → 触发生产入库（成品进 `inv_inventory_batch`）
- 事件驱动库存与成本归集

### 4. 退料
- 领料后退回仓库，冲减已领量，回写库存

## 五、核心数学逻辑

### 1. BOM 展开（`bom-expansion.ts`）
多层递归，含损耗：
$$
\begin{aligned}
\text{baseQty} &= Q_{\text{父}} \times q_{\text{单位用量}} \\
\text{累计损耗率} &= L_{\text{父累计}} + L_{\text{本层}} \\
\text{actualQty} &= \text{baseQty} \times \left(1 + \frac{\text{累计损耗率}}{100}\right)
\end{aligned}
$$

- 半成品继续展开；原材料为叶子节点
- 同物料合并累加
- 防循环引用 + 最大深度（默认10）
- 缓存：`bom:expansion:{productId}:{qty}`，TTL 600s

> **示例**：计划1000，用量0.5kg，损耗5% → 需求 = 1000×0.5×1.05 = 525 kg。

### 2. 领料/出库（FIFO）
- 需求量来自 BOM actualQty（或工单物料需求）
- 扣减顺序：余料 > 已开封 > 临期 > 入库时间
- 成本：$\sum a_b \times p_b$（Decimal）
- 乐观锁：version，冲突重试

### 3. 自动排产（基础）
优先级评分：
$$ \text{score} = f(\text{urgency},\ \text{客户},\ \text{创建天数},\ \text{齐套}) $$

**工期（问题点）**：原硬编码 $ \text{天数} \approx \lceil Q \times 0.5 \rceil$（不合理，见修复方案）。

齐套判断：BOM 行需求 vs 批次 available_qty 汇总（注意 status 字段不一致问题）。

### 4. 增强排产
- 按颜色工序 `seq_no` 顺序
- 设备类型匹配 + 依赖工序结束时间
- 工期与产能相关（公式有量纲风险，见修复）
- 时间槽搜索（默认 8:00–16:00）

### 5. MRP（概念层）
$$ \text{净需求} = \text{毛需求} - \text{在途} - \text{库存} + \text{安全库存} $$
再按提前期反推采购/生产建议单。

## 八、已知问题与修复方案（按优先级）

> 原则：先修数据契约，再修算法；工期只认一种模型；排产结果必须落库；设备/时段配置化。

### P0 — 必须立刻修

#### 问题P3：齐套查询 status='normal' 与库存模块不一致
- **现象**：有库存仍判缺料，紧急单被压后。
- **现状**：`AND status = 'normal'`（字符串），实际库存批次多使用 `status = 1`（数字）。
- **修复**：
  ```ts
  // 统一为数字常量
  AND deleted = 0 AND status = 1
  // 若多种可用状态，使用 IN (1, ...)
```

定义公共常量：`src/lib/inventory-constants.ts` 或已有枚举。

* **验收** ：批次 status=1 且充足 → material_ready=true；status=2 或已删 → 缺料。
* **测试** ：

| 编号      | 输入                            | 预期                         |
| --------- | ------------------------------- | ---------------------------- |
| FIX-S-001 | 库存100，需求50，status=1       | available=true，shortages=[] |
| FIX-S-002 | 库存100，status='normal' 字符串 | 不依赖字符串，按数字1判定    |
| FIX-S-003 | available=30，需求=50           | shortage=20                  |

#### 问题P1：基础排产工期 = 数量 × 0.5 天

* **现象** ：1000件 → 约500工作日，交期失真。
* **修复** ：采用产能模型
  工期(工作日)=max⁡(1, ⌈QC小时×H日⌉)**工期**(**工作日**)**=**max**(**1**,** **⌈**C**小时****×**H**日****Q****⌉**)
  实现函数 `estimateWorkingDays`，从设备/工艺取产能，日工时默认8。
* **验收** ：Q=100，产能50件/h，日8h → 日产能400 → 工期1天；Q=1000 → 3天。
* **测试** ：

| 编号      | Q    | 产能/h | 日工时 | 预期天数  |
| --------- | ---- | ------ | ------ | --------- |
| FIX-S-010 | 100  | 50     | 8      | 1         |
| FIX-S-011 | 1000 | 50     | 8      | 3         |
| FIX-S-012 | 1    | 1      | 8      | 1（下限） |

#### 问题P2：增强版 durationHours 量纲错误

* **现状** ：`durationHours = ceil( plan_qty / capacity * estimated_duration_hours )`，且先取 `suitableEquipment[0]` 计算。
* **修复** ：在最终选定设备后计算，方案二选一（文档写死一种）：
* **方案A（推荐）** ：`durationHours = max(1, ceil(plan_qty / capacity_per_hour))`
* **方案B** ：若工序已给总工时，直接使用 `estimated_duration_hours`（若为单件工时则乘以数量）。
* **验收** ：时长与最终设备产能一致，不再三重放大。
* **测试** ：

| 编号      | plan_qty | capacity | 策略   | 预期 duration       |
| --------- | -------- | -------- | ------ | ------------------- |
| FIX-S-020 | 200      | 50       | 产能   | 4                   |
| FIX-S-021 | 200      | 50       | 旧公式 | 禁止出现8（原误算） |

### P1 — 高优先级

#### 问题P4：设备类型/状态匹配脆弱

* **修复** ：
* 类型映射配置化（`sys_calc_param` 或表 `eqp_type_map`）
* 状态统一：`Number(eq.status) === 1 || eq.status === '1'`
* **验收** ：主数据改类型映射后无需改代码；状态数字/字符串都能匹配。

#### 问题P5：跨天时间槽/hour计算错误

* **修复** ：
* 使用完整 `Date` 比较，而非 `getHours()`
* 重叠检测用时间戳区间：`[s1,e1)` 与 `[s2,e2)` 相交判断
* 工作窗配置化（8–16），跨天拆成多段或完整起止
* **验收** ：23:00开始持续3h，结束次日02:00，与次日早班不误判/漏判重叠。

#### 问题P6：优先级与缺料排序策略不清晰

* **修复** ：统一排序键，策略二选一并固化：
* **策略A** （推荐）：紧急度优先，缺料只标记不压后，由计划员决定。
* **策略B** ：缺料工单排到有料之后，但紧急仍置顶。
* **实现** ：单一排序键，避免SQL排序+score排序冲突。
* **验收** ：urgent+缺料在策略A下排在normal+齐套之前。

### P2 — 中优先级

#### 问题P7：产能负载 DEFAULT_DAILY_CAPACITY = 1000（无量纲）

* **修复** ：按工时计算
  load%=∑占用工时∑设备日可用工时×100%**load%**=**∑**设备日可用工时**∑**占用工时****×**100%**
* **验收** ：两台设备各8h排满 → 约100%；只排一台满 → 约50%。

#### 问题P8：排产不落库

* **修复流程** ：
* `autoSchedule()` → 返回建议列表（含冲突）
* 用户确认 → `persistSchedule(results)` 写入 `prod_work_order.plan_start_date/end_date` 及设备占用表
* API：`/schedule/preview`（只算不写），`/schedule/confirm`（落库）
* **验收** ：确认后再次preview显示已占用；取消排产释放占用。

#### 问题P9：测试不足

* **最低单测集** ：齐套、基础工期、增强工期、重叠、排序、落库并发等（详见原文档表格）。

### 3. 分段测试要点

#### A. 订单与打样

* 销售订单创建（客户、产品、数量、交期）
* 打样单与销售订单关联
* 标准卡（尺寸、色序、网版、油墨、材料）
* 样品反馈（客户确认/改版）→ 可转量产
* 工艺锁定到BOM/标准卡

 **测试关注** ：打样取消是否阻断量产；标准卡变更是否影响已下采购/工单。

#### B. 采购与来料

* 请购（PR）→ 转采购单（PO）
* 到货 → 待检（待检仓或锁库存）
* IQC来料检（抽检/全检）→ 合格/让步/退货
* 合格入库 → 可用量增加，FIFO批次生成

 **测试关注** ：未IQC合格能否直接入库（应拦截）；部分合格处理；入库数量≤到货数量。

#### C. 仓储与生产用料

* 工单领料：BOM需求×(1+损耗)，FIFO扣可用
* 退料：回冲已领、回库存
* 调拨/盘点

 **测试关注** ：领料不可超可用量；退料回滚正确。

#### D. 制程与成品质量

* 开工/报工（产量/不良）
* IPQC工序节点检验（返工/报废）
* 完工（数量≤计划）
* FQC成品检 → 合格放行
* 成品入库（成品批次）

 **测试关注** ：FQC不合格不能入库/发货；报工累计与完工、入库数量勾稽；不良进不合格品处理。

#### E. 发货闭环

* 销售出库（FIFO/指定批次扣成品）
* 送货单（物流、签收）
* 对账、销售退货

 **测试关注** ：出库数量≤订单未交量且≤库存；发货后订单已交量更新。

### 4. 数量勾稽全链路断言

**text**

```
销售订单行数量 Q_so
   ≥ 打样相关占用（若占交期）
   ≥ 已转工单计划量合计 Q_wo
   ≥ 已完工/入库成品 Q_fg
   ≥ 已发货 Q_ship

采购：Q_po ≥ Q_receive ≥ Q_iqc_pass ≥ Q_inbound_raw

生产：Q_wo_plan ≥ Q_issue/BOM当量
      Q_report ≥ Q_fqc_pass ≥ Q_fg_inbound

库存：Σ available + locked + 在途逻辑 = 账实（盘点差异另计）
```

任一环断链（如IQC未过就入库、FQC未过就发货）即缺陷。

### 5. 推荐E2E场景

* **E2E-01 标准量产** ：建单→BOM→请购→PO→到货→IQC合格→入库→工单→排产→领料→报工→IPQC→FQC合格→成品入库→出库。断言一致。
* **E2E-02 打样转量产** ：打样单→标准卡→反馈OK→转订单→走E2E-01。
* **E2E-03 来料不合格** ：到货→IQC不合格→退货/不合格品，原料仓不增。
* **E2E-04 成品不合格** ：FQC不合格→不可入库/出库，返工/报废可追踪。

### 6. 最高风险点（测试优先）

| 风险              | 说明                                       |
| ----------------- | ------------------------------------------ |
| 质检门禁          | 未IQC/FQC是否仍能入库/发货                 |
| 数量三单匹配      | PO↔入库、工单↔领料↔完工、订单↔发货     |
| 批次/FIFO         | 来料批次→成品批次→发货的追溯             |
| 打样与量产工艺    | 标准卡变更后旧PO/工单是否仍用旧工艺        |
| 状态回滚          | 反审核入库、取消发货后库存与订单量回滚完整 |
| 表名/status不一致 | 与已知DATA/库存status问题叠加              |
