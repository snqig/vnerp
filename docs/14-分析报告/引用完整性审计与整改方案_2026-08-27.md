## 〇、最重要结论（先读）

用户附带的审查 SQL 是**通用模板**，与本项目真实库 schema **严重不符**，直接执行会 0 行返回或报 `Unknown column`。三个核心误判：

| 模板假设 | 真实情况 | 影响 |
| --- | --- | --- |
| 库存明细有 `batch_id` 整数 FK 列 | **没有该列**；`inv_inbound_item`/`inv_outbound_item`/`inv_inventory_transaction`/`inv_transfer_item`/`prd_material_issue_item` 全用 **`batch_no`（字符串）** 关联批次 | "批次 ID 全线缺失"前提不成立；无法按 `batch_id` 回填 |
| 入库/出库明细有 `warehouse_id` 列 | **明细表无 `warehouse_id`**（入库/出库/领料/调拨明细均无） | "主从仓库不一致"检查无意义；仓库只在表头 + 批次 |
| 有 `original_inbound_date` 列、流水用 `biz_type`/`biz_id` | 真实列是 `inbound_date`/`produce_date`；流水用 `trans_type`/`source_type`/`source_id` | FIFO / 累加对账 SQL 需改写 |

**真实审计结论**：本库**不存在**"批次 ID 大面积缺失、引用全面断裂"。仅有的两个整数 `batch_id` FK（`split_order.parent_batch_id`、`split_order_detail.child_batch_id`）**完全干净（0 悬空）**。绝大多数告警来自 **E2E 测试直连 live DB 的污染**（与先前"12 缺口"同源），应走 P2-③ 测试库隔离根治，**不应盲回填**。真正需治理的只有 **4 类微小真实悬空引用**。

## 二、库存三大逻辑审计结论

| 逻辑 | 结论 | 说明 |
| --- | --- | --- |
| 入库累加 | **1 处缺口**（种子单 `IB-2026-08-25-SEED-01`，doc 50 vs batch 0） | 真实业务单未现累加缺口；种子数据未完全落库 |

### 应用层（中期，堵增量，安全高价值）
- DTO 层：所有关联 ID 加非空 + 存在性校验

### 数据库层（长期，兜底，**铁律**）
- **仅用原生 SQL `ALTER TABLE … ADD CONSTRAINT …`** 增加 FK（`ON DELETE RESTRICT`）
- **绝对禁止 `drizzle-kit push`/`generate`/`migrate`**（Drizzle schema 0 FK 知识，会 DROP 现有 129 FK，由 `scripts/guard-drizzle-kit.cjs` 拦截）

- 软删除场景：查询过滤 `deleted=0`，应用层加引用有效性校验
