# BUG-AUTH-001：「不输入用户名密码也能进入系统」根因与修复

> 2026-09-16 · 运行时探针实证（非静态推测），修复经 HTTP + 隔离双路验证

## 一、根因（三层叠加）

| # | 事实 | 证据 |
|---|---|---|
| 1 | 登录 cookie **固定 24h**，与「记住我」无关——前端 `AuthContext.login` 只传 `{username,password}`，rememberMe 从未到后端 | `login/route.ts:408` 无条件 `maxAge: ACCESS_COOKIE_MAX_AGE`（=JWT_ACCESS_TOKEN_TTL 默认 24h） |
| 2 | 9-15 修 BUG-006「Dashboard 转圈」时新增 **SSR 菜单预取**（`layout.tsx prefetchMenus`）+ **proxy 页面守卫**（仅查 cookie 存在性，不验 JWT） | `proxy.ts:148` 注释自认「只校验 cookie 存在性」 |
| 3 | SSR 预取 `getMenusByToken` → `verifyTokenLight` **只验签名+过期，不查黑名单**（黑名单只在 API 侧 `api-auth.ts` 查） | 探针 [5b]：已拉黑 token 作 cookie 硬闯 `/dashboard` → 200 + SSR 注入完整菜单 |

**叠加效应**：登录一次 → 24h cookie 常驻 → 重开浏览器/新标签/直接输 URL → SSR 自动预取菜单直接进系统；甚至访问 `/login` 被 proxy 弹回 `/dashboard`（探针 [4]）。昨日修复把「免登」从 SPA 内部现象升级成了全站硬导航行为。

## 二、修复（用户选定：落地「记住我」语义 + 一并修黑名单）

| 文件 | 改动 |
|---|---|
| `src/app/api/auth/login/route.ts` | 接收 `body.rememberMe`（缺省 true 向后兼容）；不勾 → cookie 无 maxAge（**浏览器会话级，关浏览器即失效**）；勾选 → 24h |
| `src/app/api/auth/refresh/route.ts` | 同样按 `rememberMe` 下发 cookie，防止无感刷新把会话登录「升级」成持久 cookie |
| `src/contexts/AuthContext.tsx` | login 请求体透传 `rememberMe` |
| `src/lib/auth-fetch.ts` | refresh 请求透传 `rememberMe`（按 token 所在 storage 推断） |
| `src/lib/menu-service.ts` | `getMenusByToken` 补 `isTokenRevoked`（键与 logout 路由一致）+ `isUserTokensRevoked`（改密/锁定场景） |
| `src/lib/auth.ts` | `verifyTokenLight` 补返 `iat`（用户级撤销判定需要） |
| `src/infrastructure/cache/CacheManager.ts` | **单例挂 `globalThis`**（Next.js 官方 HMR 单例模式） |

## 三、验证结果

**HTTP 探针（dev :5000）**
- A 组「记住我」cookie 语义 **4/4**：false → 无 Max-Age（会话级）；true/缺省 → Max-Age=86400
- B 组 SSR 黑名单：登出（拉黑）后旧 cookie 硬闯 `/dashboard` → **SSR 不再注入菜单** ✅
- C 组正常会话回归：有效 cookie 正常进入、`/login` 弹回 dashboard（既有行为）、仅 cookie 调 API 200、无凭证 307 → /login ✅

**隔离验证（tsx 同进程）4/4**：有效 token 出菜单 / 拉黑后 null / 同用户另一 token 不受影响 / 用户级撤销（改密）后 null

**门禁**：`tsc --noEmit` = **1201 基线，0 新增**；CacheManager 相关存量单测 **10/10**

## 四、验证过程中的关键发现（HMR 单例分裂）

首次 HTTP 验证 B2 假阴性：隔离验证逻辑正确但 dev server 上拉黑检查不生效。根因：`CacheManager` 的 `globalCache` 是**模块级 `let`**，Turbopack HMR 重编译后模块实例重建 → 登出路由写入的黑名单与 SSR 链读取的**不是同一个实例**。已按 Next.js 官方模式挂 `globalThis`（`globalForCache.__vnerpCacheManager`）修复，重探通过。

> 教训：dev 环境跨路由的内存单例必须放 `globalThis`，否则 HMR 后的运行时验证结果不可信。

## 五、残留（已知、可接受）

1. `proxy.ts` 页面守卫仍只查 cookie 存在性——Edge runtime 无法读 Node 进程的内存黑名单，SSR 预取已是权威防线（黑名单 token 进不了系统）
2. 浏览器后退键（bfcache）可能显示登出前的页面外壳——任何 API 调用会 401 并弹回登录，数据拿不到
3. `revokeToken`/`revokeAllUserTokens` 内部调 `getTranslations` 仅为打日志——脱离 Next 请求上下文不可复用（本次隔离验证已绕开），建议后续把日志改纯文本
