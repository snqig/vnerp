## 2 · P1 成本回填：先修数据，但真因是代码查了不存在的列

### 2.1 「BOM/配方成本恒为 0」的真实因果链

全仓成本读取点只有两处，**都读 `inv_material`，与 `std_material` 无关**：

| 读取点 | 文件 | 读的列 |
|---|---|---|
| 工单成本分摊 | `src/services/CostAmortizationService.ts:222` | `inv_material.cost_price` |
| 油墨/BOM 配方成本 | `src/infrastructure/providers/MaterialCostProvider.ts:26` | `inv_material.weighted_avg_cost` → 降级 `base_ink.unit_price` |

而实测：

| 事实 | 值 |
|---|---|
| `inv_material.weighted_avg_cost` 列 | **不存在**（`information_schema` 无此列，`SHOW` 报 errno 1054） |
| `MaterialCostProvider` 主查询后果 | 抛 `ER_BAD_FIELD_ERROR` → 被 `catch {}` **静默吞掉** → 走降级 |
| `base_ink` | 3 行，`unit_price>0` 的 **0 行** |
| ⇒ 配方成本 | **恒为 0**（两个来源都拿不到值） |
| `std_material.unit_cost` 读取点 | **0 处**（只有 DDL + CRUD，无任何成本计算引用） |

`MaterialCostProvider` 确实接在活的调用链上：`InkFormulaVersionService.ts:30/124` → `FormulaCostService:64`。
