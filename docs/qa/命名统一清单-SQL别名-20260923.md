# 命名统一清单：SQL camelCase 别名 → snake_case

> 生成时间：2026-09-23（基于源码静态扫描，SQL 字符串内 `AS <alias>` 口径）
> 范围：`src/` 全量；已剔除 `CAST(x AS UNSIGNED)` 等类型转换关键字

## 一、总体规模

| 指标 | 数值 |
|---|---|
| 涉及文件 | **27** 个 |
| 不同别名 | **311** 个 |
| 出现处数 | **343** 处 |

## 二、分层结论

- **数据库层：已完成** —— 全库 302 张表、5141 列中，驼峰列名 **0 个**、驼峰表名 **0 个**，已是纯 snake_case。
- **SQL 别名层：未统一** —— 上述 311 个别名会把驼峰键写进 API 响应 JSON，与库内 snake_case 列名形成双套命名。
- **迁移状态：中途** —— 部分前端页面已改为「双读兜底」（`item.cardNo || item.card_no`），部分尚未，故**不能一次性批量改名**。

## 三、风险分级（决定执行顺序）

| 等级 | 判据 | 处理方式 |
|---|---|---|
| 🟢 可安全改名 | 消费端已双读，或别名仅在服务端内部使用 | 直接改别名 + 改内部引用 |
| 🟡 需同步改消费端 | 消费端只读驼峰 | 改别名 **同时**改前端读取键 |
| 🔴 暂缓 | 别名参与动态键拼接 / 跨模块共用 / 已被外部集成消费 | 需先评估 |

## 五、执行建议

1. **按模块分批**，每批一个 API 文件 + 其页面，改完立即 grep 消费端并跑 tsc。
2. **优先处理已双读的模块**（Quality process / final、dcprint、warehouse 部分路由）——改动即可生效且可回滚。
3. **未双读的模块**（如 `quality/incoming`、`dcprint/scan`）需同时改前端，建议成对提交。
4. 改完用运行时抓包核对响应 JSON 键，勿只看 tsc（别名改名 tsc 查不出）。

> 注：本清单只覆盖「SQL 别名」这一层。TS 侧接口/变量名按语言规范保持驼峰，不在统一范围内。
