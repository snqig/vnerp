### 成因

i18n codemod 把含中文 `COMMENT '...'` 的 SQL 字面量当成"硬编码中文"抽出，合成为 `k_xxxxxxxx` 键塞进 `Common` 命名空间。**改 messages 文件 = 改实际执行的 DDL**。

### 处置方案（推荐）

1. 新建 `src/lib/db/ddl/` 目录，按模块拆常量文件（如 `init-full-tables.ts`、`migrations.ts`、`seeds.ts`），导出带语义名的常量
2. 40 个引用点改为 `import { XXX_DDL } from '@/lib/db/ddl/...'`
3. 从四语言 `messages/*.json` 删除这 283 个键
4. 回归：tsc / vitest / lint-gate / i18n-key-check + 运行时断言「DDL 端点仍可建表」

**分批建议**：`init/*`（19 个路由，量最大）→ `migrations/*`（4 个）→ `dcprint/warehouse/orders/outsource/hr`（13 个）→ 4 个业务模块

对 784 条做名称关键词归类：

| 类型 | 命中数 |
|---|---|
| **网版** | **30** |
| 薄膜 | 3 |
| **油墨** | **0** |
| **刀模** | **0** |

### 结论

报告「网版 / 油墨 / 刀模仍可分切」中——**只有"网版"属实**（30 条，`material_name='网版'`，`material_code` 为纯数字如 `1`/`4`/`5`）；**油墨与刀模不属实**（

- 油墨子类 `category_id=5` 下**无任何物料**；刀模关键词命中 **0**）。

根因：`is_splittable` 是**按分类粗粒度批量写入**的（整个"原材料"分类=1），不是按物料类型逐条判定。

**需你决策**：网版是否应禁止分切？若"应禁止"，建议只改这 30 条（精准、可回滚）；若要更彻底，则整个"原材料"分类需按类型重新逐条判定（784 条）。
