## P1 — 结构性违规

### 2.1 选择框两套实现并存（规范 3 最大违规面）

- `useRowSelection`（`@/lib/useRowSelection`）：32 页在用
- 自建 `useState(selectedIds/selectedRecords)`：**28 页**（warehouse/inventory、quality×7、sample×3、purchase×2、hr/attendance、hr/salary、orders/customers、srm/evaluation、outsource/issue、dcprint/ink、business/contract-review、prepress/die-template、production/product-label、warehouse/transfer|outbound|stocktaking|stock-adjust|inbound/cutting）

且自建版形态还不统一（`Set<number>` / `number[]` / `string[]` 三种）。**建议**：分批收敛到 `useRowSelection`，优先处理同时带批量删除语义的页面。

### 2.2 console.* 全量统计（规范 5）

61 处 / 35 文件，热点：
- `lib/audit-logger.ts` ×9 — 日志失败兜底（自身是日志器，降级可接受，但应换 `logger`）
- `sample/standard-card` 系列 ×13 — 调试残留
- `auth/login|logout|refresh` ×4 — error 对象直打印
- 其余散布 domain/application/infrastructure 层

`@/lib/logger`（pino + `maskSensitiveData` + `stepStart/stepEnd/db/branch`）能力完备却近乎零使用。**建议**：服务端 `console.*` 全量迁 `logger`；客户端（浏览器组件）保留允许清单或引轻量封装。

### 2.3 any 债（规范 4）

热点：`StandardCardApplicationService` ×10、`SagaCompensationHandler` ×9、`DeadlockMonitor` ×4、`login/route.test.ts` ×14（测试可豁免或后置）。生产代码约 55 处可按 unknown + 类型守卫消化。
