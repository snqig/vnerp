# 质量模块 6 列表「类型列」i18n 修复 — 运行时验证报告

**日期**：2026-09-21｜**模块**：`/quality/*` 六个列表页

## 1. 现象
6 个质量列表页的「类型列」显示为数据库原始枚举码（英文/数字），而非译文：

| 页面 | 列 | 原显示（原始码） |
|---|---|---|
| complaint | 缺陷类型 | delivery / quality / service |
| supplier-audit | 审核类型 | annual |
| lab-test | 测试类型 | physical / chemical / environmental |
| unqualified | 处理方法 | 1 / 2 / 3 |
| incoming | 检验类型 | appearance |
| trace | 类型 | forward（按数字 1/2 匹配失败） |

## 2. 根因（DB 直连复核）
列表单元 `t(map[value] || value)`：当 `map` 的 key **不含**真实存储值时，回退显示原始存储码。两类错配：
1. **字段名错**：complaint 旧代码用 `defect_type`，DB 实为 `complaint_type`。
2. **枚举值错**：trace 的 `trace_type` 是字符串 `'forward'`，旧 `map` 按数字 `1/2` 匹配 → 全 fallback。
DB 真实枚举（实测）：`qms_complaint.complaint_type∈{quality,delivery,service}`、`qms_supplier_audit.audit_type=annual`、`qms_lab_test.test_type∈{physical,chemical,environmental}`、`qc_unqualified.handle_type∈{1,2,3}`、`qc_incoming_inspection.inspection_type=appearance`、`inv_trace_record.trace_type='forward'`。

## 3. 修复
- 6 页 `*TypeMap` 的 key 重写为真实 DB 枚举；下拉对齐真实枚举并补充合理完整选项（单值列扩成完整集）。
- `api/quality/complaint/route.ts`：`defect_type`→`complaint_type` 贯穿；默认值 `'other'`→`'quality'`（避免落脏值）。
- `trace/page.tsx` 接口 `trace_type: number`→`string | number`（解 number/string 比较 tsc 报错）。
- 四语 `messages/{zh-CN,en,vi,zh-TW}.json` 补 **10** 键：`complaintTypeDelivery/Quality/Service`、`auditTypeAnnual`、`physical/chemical/environmentalTest`、`scrap`、`return`、`appearanceInspection`。
